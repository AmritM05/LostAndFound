## Actual provider and modality behavior

Official @google/genai SDK uses models.embedContent with model gemini-embedding-2 and outputDimensionality 768. Each request contains one Content so distinct reports/modalities are never accidentally aggregated together. Text inputs use the item name and nonempty private item description, capped at 5,000 characters; no ownership answers, report_notes, private_report_details, identity/contact, coordinates or staff notes are sent. Missing descriptions skip text inference. Vectors must have exactly 768 finite values and a nonzero finite norm; they are normalized again defensively. Cosine is clamped to [-1,1], then negative values are clipped to zero for the existing [0,1] ranking-signal contract.

At most one bound uploaded photo per report is used initially. Metadata must match that report, its reporter and the correct student/admin upload role. Existing private Vercel Blob access uses server-held pathnames, never client URLs; the Google request contains prepared bytes, not private Blob URLs. Optional private WebP previews are preferred. Original JPEG/PNG/WebP and HEIC/HEIF are supported: sharp prepares JPEG output; heic-decode handles HEIC/HEIF primary frames with dimension checks before raw pixel expansion. JPEG output is stripped of metadata, resized within 1024×1024 and quality 80, capped at 2 MB. Original input is capped at the existing 25 MB and 24 million decoded pixels for AI; larger dimensions or decoder failures omit the image signal safely. Existing original upload/download, HEIC and 25 MB upload acceptance are unchanged. The HEIC conversion branch has mocked-decoder coverage, not a claimed fresh real-device codec test.

Both photos produce visual similarity. One photo and an opposite report description produce image-to-text similarity in the same embedding space. Both descriptions produce semantic similarity. Partial modality failure can still use a successful measured modality; if none succeed, exact deterministic fallback applies. Camera-angle/object-recognition quality requires actual synthetic object photographs and live evaluation; transport tests and color swatches do not prove it.

## Authorization, consent and privacy limits

POST /api/admin/ai-matching/ accepts **only** {lostId,foundId,confirmSynthetic:true}; UUIDs, admin session and allowed Origin are required. Arbitrary URLs, embeddings, descriptions or score inputs are rejected. Students cannot directly trigger inference on another student's report/photos. Existing demo staff have broad authorized access; this is not a new per-desk/tenant permission system.

Three explicit controls precede egress: server AI enabled, server synthetic-demo mode enabled, and staff confirmation that both selected reports/descriptions/photos are synthetic and permitted for Google processing. Report forms and the staff comparison UI display the processing notice. A key alone is insufficient. Real-user processing is unsupported: do not enable this workflow on real reports. A production rollout requires report-owner opt-in/revocation, a reviewed Google data-processing/retention arrangement, stronger verified identity, and enforcement of consent scope; staff synthetic attestation is not real-user consent. No automated public inference, provider file upload, public Blob conversion or silent background processing was introduced.

Vectors are transient server-only cache data and never sent to students or persisted in a vector database. Stored staff_reasoning.ai includes provider/model/dimensions, successful channels, configured weights, demo confirmation actor, scoring version and assessment time—no vectors, images, prompts, URLs or key. Owner/public DTOs keep their existing whitelist. New candidates generate only the existing generic owner notice. Provider errors are collapsed to safe fallback reasons; keys and request bodies are not logged.

## Reliability and persistence

- Provider deadline 5 seconds per attempt, SDK automatic retries disabled, one extra attempt only for 429/500/502/503/504, short bounded delay. Abort/race handles unavailable clients. Private Blob reads and image preparation are bounded; native conversion has a processing timeout and pixel cap. HEIC parsing is local CPU work, so malformed-heavy production files still need stronger worker isolation before production use.
- Two active comparisons and one per staff actor; provider concurrency two with a bounded queue and queue timeout. No scheduler, report-write blocking, vector DB or autonomous paid calls.
- Process-local LRU caches up to 128 vectors for ten minutes and tracks at most 256 report revisions. In-flight work is deduplicated. Keys include report/revision/modality/model/dimensions. Changed content/photo metadata selects a new revision; owner edit/delete explicitly invalidate, and in-flight invalidated results cannot repopulate cache. Cache resets on process restart; separate serverless instances may repeat requests. No failed response is cached.
- 008 locks reports and rechecks current compatibility, lifecycle, dismissal and active claims. Optimistic revision checks reject changes/deletion during inference. It computes scores server-side with the existing SQL evaluator and only then applies measured factors; no supplied client score is trusted. It preserves manual dismissals, active recovery and terminal states, creates candidates only at 60+, and avoids duplicate notices. Successful provenance is stored only when actual usable signals contributed. Missing or failed AI invokes unchanged deterministic scoring and clears an older AI label when that fallback is applied.
- Existing deterministic report-update triggers replace old reasoning, naturally invalidating stale AI provenance. Sorted migration replay recomputes deterministic active-pair reasoning; rerun a permitted staff comparison afterward if AI evidence is wanted. No inference happens in SQL. 008 can be replayed, changes no 004/006 recovery function and requires no data backfill. Forward fixes should use a subsequent reviewed migration; disabling both AI flags preserves report/intake and deterministic matching. Remote 005–008 deployment remains a separate authorized step.
